## variant.py — Индивидуальный вариант 8: Фотопечать

### Входные данные
Название заказа, имя заказчика, две позиции (название, количество, цена), доставка, внесённая сумма.

### Расчёты
- Стоимость позиции: `количество * цена`.
- Товары без доставки: сумма стоимостей.
- Итого: товары + доставка.
- Общее количество: сумма количеств.
- Сдача: внесено − итого.

### Основной пример

| Поле | Значение |
|---|---|
| Заказ | Фотопечать |
| Заказчик | Анна |
| Позиция 1 | Малые фотографии, 3 × 12.50 |
| Позиция 2 | Большие фотографии, 2 × 20.00 |
| Доставка | 10.00 |
| Внесено | 100.00 |

**Ручной расчёт:** 37.50; 40.00; 77.50; 87.50; 5; 12.50.

### Проверки

| № | Случай | Ожидалось | Факт |
|---|---|---|---|
| 1 | Основной пример | 37.50; 40.00; 77.50; 87.50; 5; 12.50 | совпадает |
| 2 | Нулевое количество позиции 1 | 0.00; 100.00; 100.00; 105.00; 4; 5.00 | совпадает |
| 3 | Нулевая доставка | 80.00; 75.00; 155.00; 155.00; 15; 0.00 | совпадает |
| 4 | Точная оплата | 20.00; 60.00; 80.00; 90.00; 5; 0.00 | совпадает |
| 5 | Названия из нескольких слов | 36.00; 36.00; 72.00; 79.50; 6; 0.50 | совпадает |


## Пояснения

### Строка и число
`input()` возвращает `str`. Для расчётов нужны `int()` (целые) или `float()` (дробные). Без преобразования `"3" + "2"` даст `"32"`.

### Порядок вычислений
Сначала умножение/деление, затем сложение/вычитание. Скобки меняют порядок: `(a + b + c) / 3`.

### Временная переменная при обмене
`temp` сохраняет одно значение, пока другое записывается на его место, иначе первое будет потеряно.

### Форматирование денег
`{value:.2f}` выводит число с двумя знаками после точки.

### 3. Предскажите результат (ручной расчёт vs Python)

| Выражение | Ручной прогноз | Результат Python | Объяснение |
|---|---|---|---|
| `2 + 3 * 4` | 14 | 14 | Умножение имеет приоритет над сложением. |
| `(2 + 3) * 4` | 20 | 20 | Скобки меняют порядок вычислений. |

### 4. Индивидуальный вариант (`variant.py`)
**Задача:** рассчитать количество полных комплектов заданий, остаток и минимальное количество комплектов для размещения всех заданий.

**Формула для округления вверх:**  
Минимальное число единиц = `(total + capacity - 1) // capacity` (при `total > 0`).  
Эта формула позволяет получить округление вверх без использования условных операторов или циклов.

**Примеры проверок:**

## minimum.py

Ввод: три целых числа.
Вывод: минимальное из них.

### Пояснение
Используются последовательные ветки `if / elif / else`. Каждое число сравнивается с двумя другими через `and`. Равные значения обрабатываются через `<=`.

| 2, 10, 3 | 2 | 2 |
| 5, 5, 5 | 5 | 5 |

## calculator.py

Ввод: два вещественных числа и символ операции.
Вывод: результат с двумя знаками.

### Пояснение
Внешняя цепочка `if / elif / else` выбирает операцию. Внутри деления — вложенная проверка на ноль. `eval()` не используется, операции задаются вручную.

| a | b | операция | Ожидалось | Факт |
|---|---|---|---|---|
| 7 | 2 | / | 3.50 | 3.50 |
| 5 | 0 | / | Деление на ноль запрещено | Деление на ноль запрещено |
| 5 | 2 | ? | Неизвестная операция | Неизвестная операция |
| 5 | 2 | + | 7.00 | 7.00 |
| 5 | 2 | - | 3.00 | 3.00 |
| 5 | 2 | * | 10.00 | 10.00 |

## variant.py — Вариант 8: Заполнение группы

Категории:
- 0–39 — `Есть места`
- 40–79 — `Группа набирается`
- 80–100 — `Почти заполнена`
- вне 0–100 — `Ошибка диапазона`

### Пояснение
Первое условие отсекает выход за диапазон. Далее цепочка `elif` разбирает категории по порядку. Верхние границы уже проверены первым условием, поэтому в `elif` достаточно одного сравнения.

| Вход | Ожидалось | Факт |
|---|---|---|
| -1 | Ошибка диапазона | Ошибка диапазона |
| 0 | Есть места | Есть места |
| 39 | Есть места | Есть места |
| 40 | Группа набирается | Группа набирается |
| 79 | Группа набирается | Группа набирается |
| 80 | Почти заполнена | Почти заполнена |
| 100 | Почти заполнена | Почти заполнена |
| 101 | Ошибка диапазона | Ошибка диапазона |
